# 游戏中的延迟与倒计时

角色死亡后等三秒复活，获得物品后显示两秒提示，每秒刷新一次附近目标——这些都可以交给 Timer。它只负责“到时间调用一个方法”，复活、关闭 UI、刷新目标仍由你的游戏代码完成。

## 从延迟复活开始

```csharp
// timers 是启动代码传入的 TimerScheduler，RevivePlayer 是你的复活方法。
TimerHandle revive = timers.ScheduleOnce(3, RevivePlayer);
revive.Pause();    // 保留剩余时间。
revive.Reset();    // 重新变为 3 秒，仍然暂停。
revive.Resume();   // 接着计时。
```

剩余时间通过 `revive.RemainingSeconds` 读取，状态通过 `revive.State` 读取。它们随计时器推进更新，不会自行读取系统时间。任务完成或取消后不能 Reset，下一次死亡重新 ScheduleOnce。

周期行为用 `timers.ScheduleRepeating(1, RefreshTargets)`，第一次也会等待一秒。卡顿三秒不会补刷新三次：本轮最多一次，然后重新等待完整一秒。这不适合要求每一步都必须计算的伤害结算或物理模拟。

## 谁推进时间

普通 C# 中由拥有者调用 `AdvanceTime(deltaSeconds)`；所有操作都在创建线程进行。以下是完整的最小调用示例：

```csharp
using System;
using GameSysLab.Modules.Timer;

public static class RespawnTimingExample
{
    public static void Run(Action revivePlayer)
    {
        using (var timers = new TimerScheduler())
        {
            timers.ScheduleOnce(3, revivePlayer);
            timers.AdvanceTime(2); // 尚未复活。
            timers.AdvanceTime(1); // 执行复活方法。
        }
    }
}
```

真实游戏不要写死每帧推进一秒。在 Unity 中使用下面的 Host，让它传入真实的帧时间增量。

## Unity 里挂什么、怎么调

1. 给关卡中的“关卡计时”GameObject 添加 TimerHost。只有 Host 是组件，Scheduler 和 Handle 都不用挂载。
2. Inspector 的 Time Mode 默认 GameTime，游戏暂停时一起暂停。菜单提示使用另一个 Host，选 UnscaledTime。
3. 在你的启动脚本声明 `[SerializeField] private TimerHost gameTimerHost;`，将对应 Host 拖入该引用。
4. 启动时调用 `TimerScheduler gameTimers = gameTimerHost.Initialize();`，把 gameTimers 传给需要计时的角色或界面。
5. 退出关卡时先取消各对象的任务，再由拥有者调用 `gameTimerHost.Shutdown()`。

使用程序集：业务代码引用 `GameSysLab.Modules.Timer`；Unity 启动代码再引用 `GameSysLab.Modules.Timer.Unity`。管理一组任务时可额外使用现有 Lifecycle，Timer 本身不依赖它。

模式在 Initialize 时固定，之后改 Inspector 不切换当前实例。动态创建时可在 Initialize 前设置 `host.TimeMode = TimerTimeMode.UnscaledTime`。没有全局查询入口，同一个时间实例由启动代码显式传给使用者。

## 界面关闭时取消自己的任务

```csharp
// menuTimers 是未缩放时间的 Scheduler；HideTip 由你的 UI 实现。
var windowLifetime = new GameSysLab.Core.Lifecycle.Lifetime();
windowLifetime.Add(menuTimers.ScheduleOnce(2, HideTip));

// 窗口提前关闭时执行，避免两秒后访问已退出的界面。
windowLifetime.Dispose();
```

下一次打开窗口创建新的 Lifetime。不能把借用的 Scheduler 加入窗口集合，否则窗口关闭会把其他对象的任务也取消。频繁重建一个倒计时时，直接保存当前句柄、替换前 Cancel，避免长寿集合积累历史句柄。

## 暂停、禁用与退出的区别

| 操作 | 结果 |
| --- | --- |
| `handle.Pause()` | 只暂停这一件任务 |
| `Time.timeScale = 0` | GameTime Host 不前进，UnscaledTime Host 继续 |
| 禁用 Host | 暂停该 Host 自动推进，恢复不补时间；任务没有被取消 |
| `handle.Cancel()` 或 Dispose | 永久结束这一件任务，不能复活 |
| `host.Shutdown()` | 永久结束该 Host 的全部未完成任务，需要新 Host 才能重建 |

不要在界面每次打开时 new 一个没有人推进的 Scheduler。也不要一边使用 Host.Update，一边再次手动推进同一个实例。

## 几个明确的边界

- 所有时长单位为秒，必须为有限正数；AdvanceTime 可以传 0，但不会执行任务。
- 回调只能是单个同步 Action。不能传 async void；耗时操作由独立服务承担。
- 同一轮多个任务到期按创建顺序执行；先统一更新时间，回调中创建的任务下轮才开始计时。
- 一个回调失败不会挡住其他到期任务，最后汇总抛错。Host 会写入 Console；自行推进时由调用方捕获 AggregateException。循环任务失败后仍保留下一周期。
- 计时器没有抢占或每帧数量预算，大量到期或很慢的回调仍会卡住主线程。

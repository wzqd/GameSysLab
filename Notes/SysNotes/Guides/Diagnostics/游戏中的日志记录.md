# 游戏中的日志记录

角色创建失败、窗口缺少图标、关卡准备完成时，用日志说明发生了什么。每个使用者创建自己的日志入口；它不会自动查找其他模块，也不会改变游戏状态。

## 最简单的用法

在自己的 Unity 组件中使用，以下是方法内片段：

```csharp
var log = new GameSysLab.Modules.Diagnostics.Logger(
    "角色生成", new GameSysLab.Modules.Diagnostics.Unity.UnityConsoleSink());

log.Info("角色准备完成");
log.Warning("缺少头像，使用默认图标");
log.Error("创建失败", new System.InvalidOperationException("角色配置不完整"));
```

Console 会显示 `[角色生成] 角色准备完成`。模块名只填一次。异常与原始堆栈附在错误消息后，不重新抛出业务异常。

## 少输出，少做无用工作

```csharp
log.MinimumLevel = GameSysLab.Modules.Diagnostics.LogLevel.Warning;
log.Info("这条被过滤");
log.MinimumLevel = GameSysLab.Modules.Diagnostics.LogLevel.None; // 关闭输出
```

详细消息计算较贵时，使用延迟构造：

```csharp
log.WriteLazy(GameSysLab.Modules.Diagnostics.LogLevel.Info,
    () => "只有启用 Info 才构造这段内容");
```

普通字符串插值发生在调用之前，不会因过滤自动省掉。延迟函数里的计算会跳过，但创建闭包或委托仍可能有分配；没有零分配承诺。

## 接入其他模块时

其他模块无需引用 Diagnostics。装配入口可把它们已有的错误回调接到 `log.Error`。以下是普通 C# 回调的示意，不要求修改已有模块接口：

```csharp
System.Action<System.Exception> reportError = error => log.Error("操作失败", error);
// 把 reportError 传给支持该回调的对象。
```

需要自定义输出时实现 `ILogSink.Write(LogEntry)`，传给 Logger 即可。Logger 借用输出器，不负责 Dispose；若自定义输出器持有文件等资源，由创建者释放。

## Unity 中如何安装

Logger 和 UnityConsoleSink 都是普通 C# 类，不挂载，无必填 Inspector 引用。由自己的组件或装配入口在主线程创建并保存 Logger。默认最低级别 Info，可运行时修改；不用 Update 推进，不订阅 Unity 日志回调。退出时放弃引用即可；模块无静态实例、无缓存队列、无文件句柄。

有 asmdef 的调用方引用 `GameSysLab.Modules.Diagnostics`；Unity 输出再引用 `GameSysLab.Modules.Diagnostics.Unity`。纯 C# 代码只需要前者。使用 `UnityEngine` 时可用 Logger 类型别名，避免与 UnityEngine.Logger 重名。

## 输出失败怎么办

调用返回 true 表示输出器同步返回成功，不保证第三方输出器已持久化。false 表示被过滤、输出失败或递归输出被拒绝。业务不能根据日志返回值决定伤害、扣款等结果。

输出器或延迟消息函数抛异常时，Logger 保存 `LastFailure` 并增加 `FailureCount`，不覆盖业务异常；修复输出器后可以继续记录。`ClearFailures()` 清除计数和最后异常引用，不改变过滤设置。不自动向同一个日志入口报告输出错误，避免递归。

所有 Logger 操作限创建线程；UnityConsoleSink 在主线程创建并使用。错误线程、非法级别和启用级别下的空消息是调用错误，会抛异常。关闭级别不会执行或检查消息内容。错误级别也可以过滤。

本模块没有文件输出、远程上报、自动状态采集或操作追踪。池的计数与 Timer 状态仍由各自模块提供。

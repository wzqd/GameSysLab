# Core 生命周期

## 研究问题

Demo 如何显式创建服务，在正常退出或启动失败时释放资源，并能干净地重新进入？

## 范围

一个入口、两个有顺序关系的示例服务，以及可观察的操作记录。服务使用普通对象，不强制统一 BaseSystem。只研究同步生命周期，不包括异步加载、热更新、全局服务查找或具体玩法。

## 所有权与状态约定

入口拥有创建成功并接收的资源。资源按取得顺序记录、逆序释放；初始化失败的服务负责清理自己未移交的资源。外部借用对象不被重复释放。

状态示意：未启动 → 启动中 → 运行中 → 停止中 → 已停止；启动失败先清理再进入失败状态。停止后的下一轮使用新实例。

不变量：每个已取得资源最多释放一次；单项清理失败不阻断其他清理；退出后没有本实验遗留的订阅。

## 验收例子（待执行）

| 场景 | 预期 |
| --- | --- |
| A 成功后 B 成功 | 按 A、B 顺序取得，按 B、A 顺序释放 |
| A 成功，B 初始化失败 | B 清理自身部分资源，入口释放 A，保留失败信息 |
| B 释放抛出异常 | 仍尝试释放 A，记录 B 的错误 |
| 连续停止两次 | 不重复释放或重复解除订阅 |
| 退出后重新进入 | 新实例独立启动，没有上次状态或重复通知 |

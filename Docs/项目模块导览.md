# 游戏系统模块导览

这份文档按游戏开发中的实际用途介绍模块。它是一张项目地图，不代表下面所有模块都已实现。

## 项目现在有什么

- **日志与诊断**：独立记录消息、警告和异常，支持过滤与替换输出。[使用指南](../Notes/SysNotes/Guides/Diagnostics/游戏中的日志记录.md)。

- **事件通知**：一个对象发生变化，让关心它的对象收到消息。
- **生命周期管理**：对象或关卡退出时，清理订阅和持有的资源。
- **计时器**：延迟执行、周期执行，以及暂停和取消任务。
- **对象池**：借出、归还和复用对象，目前已有初版。

## 一、基础能力：让其他模块有清楚的边界

| 模块 | 解决什么问题 | 游戏里的例子 |
| --- | --- | --- |
| 日志与诊断 | 看清发生了什么、哪里出了问题 | 查出某次技能为什么没有释放成功 |
| 生命周期与装配 | 谁创建对象、谁提供依赖、谁负责清理 | 进入关卡创建服务，退出关卡释放 |
| 时间 | 决定某项逻辑跟随哪一种时间 | 游戏暂停时敌人停止，菜单动画继续 |
| 计时器 | 到时间执行一次或周期执行 | 三秒后复活、每秒恢复生命 |
| 更新调度 | 决定哪些逻辑何时更新、多久更新一次 | 远处敌人降低思考频率 |
| 事件通知 | 将已经发生的事情通知其他对象 | 角色受伤后，血条和音效分别响应 |
| 命令与查询 | 明确请求做什么，以及读取什么 | 请求购买物品，查询剩余金币；起步可用普通方法 |
| 配置数据 | 管理可调整、可复用的规则数据 | 武器基础伤害、敌人移动速度 |
| 稳定标识 | 在不同模块和存档中识别同一内容 | 用物品 ID 关联配置、背包与存档 |
| 随机数 | 控制随机结果，并支持复现 | 使用同一个种子生成相同地图 |
| 状态机 | 管理有限状态及其切换 | 敌人的巡逻、追击、攻击、死亡 |

## 二、资源与世界：内容怎样进入和离开游戏

| 模块 | 解决什么问题 | 游戏里的例子 |
| --- | --- | --- |
| 资源加载 | 获取资源，并明确持有和释放责任 | 加载角色 Prefab、图标、音频 |
| 异步任务协调 | 处理等待、取消、超时和过期结果 | 界面已关闭，迟到的头像不再显示 |
| 场景与关卡 | 协调进入、准备完成和退出 | 切换关卡，准备好内容后允许玩家操作 |
| 对象池 | 复用实例，减少频繁创建与销毁 | 子弹、特效、飘字反复使用 |
| 数据序列化 | 将数据转换成可保存或传输的格式 | 把存档数据编码为 JSON |
| 存档与读档 | 决定保存什么，以及怎样恢复状态 | 保存背包和任务进度，读取后恢复 |

**它们的关系：**资源加载取得 Prefab，对象池复用由它创建的实例；关卡负责组织二者的使用与退出。异步协调负责等待过程，序列化负责数据格式，存档负责游戏状态的保存和恢复。

## 三、玩法规则：游戏本身怎样运转

| 模块 | 主要职责 | 游戏里的例子 |
| --- | --- | --- |
| 输入 | 将按键和设备操作转换成游戏意图 | 键盘或手柄都能触发“闪避” |
| 移动 | 将移动意图变成实际位移 | 行走、跳跃、冲刺 |
| 属性与修正 | 计算基础值与各种加成 | 装备和增益共同影响攻击力 |
| 战斗、生命与死亡 | 处理命中、伤害和死亡结果 | 护盾吸收伤害，生命归零后死亡 |
| 技能 | 管理使用条件、消耗、冷却和释放过程 | 消耗法力释放火球 |
| 状态效果 | 管理持续效果、叠层和到期移除 | 中毒、减速、护盾、增益 |
| 背包与装备 | 管理物品数量、位置和装备归属 | 拾取药水、换上武器 |
| 任务与奖励 | 跟踪目标进度，决定何时发放奖励 | 击败三个敌人后领取金币 |
| 交互 | 选择目标并执行允许的操作 | 开门、拾取、与角色交谈 |
| 生成与波次 | 控制何时、何地生成哪些对象 | 一波敌人结束后开始下一波 |
| 对话 | 管理节点、条件和玩家选择 | 根据任务进度显示不同选项 |

**一个组合例子：**输入触发技能，技能检查属性与资源，战斗模块结算伤害，状态效果模块施加中毒，事件通知让界面和表现刷新。

## 四、界面与表现：让玩家看见并操作

| 模块 | 主要职责 | 游戏里的例子 |
| --- | --- | --- |
| 窗口与导航 | 管理窗口开关、层级、返回和焦点 | 背包上方弹出确认框 |
| 界面数据绑定与列表 | 将游戏状态显示到界面 | 血条更新、物品列表刷新 |
| 本地化 | 按语言提供文本与相关资源 | 切换中英文，刷新已打开的窗口 |
| 设置与无障碍 | 管理偏好和可操作性 | 音量、字号、按键重绑 |
| 动画适配 | 将游戏状态连接到动画系统 | 移动速度驱动走跑动画 |
| 根运动协调 | 决定动画位移与移动逻辑如何配合 | 攻击踏步时避免两边重复移动 |
| 技能时间线 | 描述技能各阶段的时间关系 | 前摇、命中窗口、后摇 |
| 演出时间线 | 编排镜头、角色和音效 | 开场过场、剧情演出 |
| 相机与反馈 | 表现观察视角和动作反馈 | 跟随、震屏、受击闪烁 |
| 音频 | 管理播放请求、混音和结束清理 | 背景音乐、脚步声、技能音效 |

**边界：**伤害是否成立由玩法决定；血条、动画和音效负责表现结果。关闭界面不应该改变已经成立的战斗结果。

## 五、导航与智能：对象怎样感知和行动

| 模块 | 主要职责 | 游戏里的例子 |
| --- | --- | --- |
| 空间查询 | 找出位置附近的候选对象 | 查找攻击范围内的敌人 |
| 寻路 | 规划从起点到目标的路线 | 绕过墙壁走向玩家 |
| 转向与避障 | 调整局部移动方向 | 多个角色行进时相互避让 |
| AI 决策 | 根据情况选择行动 | 追击、撤退、治疗或攻击 |

空间查询回答“附近有什么”，寻路回答“怎么过去”，避障处理“眼前怎么走”，AI 决策选择“现在做什么”。网格、空间哈希、KD 树等是空间查询的候选实现，不是每个游戏都要安装的独立模块。

## 六、按游戏类型选用的扩展

| 模块 | 适用需求 |
| --- | --- |
| 大数与显示 | 放置游戏中极大的数值及其格式化 |
| 经济与离线推进 | 生产、消耗、增长及离线收益 |
| 回合与行动点 | 回合顺序、行动资源和结束条件 |
| 程序化生成 | 根据种子生成地图、房间或内容 |
| 战略与单位指令 | 框选、编队、批量命令 |
| 建造与合成 | 放置占用、建造条件、材料消耗 |
| 联机与回放 | 权威状态、输入记录、同步与重播 |

这些是可选研究方向，按具体游戏需要挑选，不必全部实现。

## 七、性能工具：发现成本后再选择

- **性能分析**：定位 CPU、内存、分配和帧耗时问题。
- **池化与分配优化**：减少频繁创建产生的成本，同时控制缓存占用。
- **批处理与数据布局**：让大量相似数据更高效地处理。
- **Jobs、Burst、DOTS**：作为高负载场景的候选技术，不是默认架构前提。

对象池处理复用，异步加载安排资源获取，空间索引减少查询范围；它们分别针对不同成本，不能互相替代。

## 在仓库里怎么找

| 位置 | 放什么 |
| --- | --- |
| `SysLab/Assets/_Lab/Core` | 少量公共基础，目前是事件与生命周期 |
| `SysLab/Assets/_Lab/Modules` | 可独立选用的基础能力，如 Timer、Pooling |
| `Systems`（按需建立） | 背包、技能、任务等玩法规则 |
| `Integrations`（按需建立） | 多个模块之间的协作逻辑 |
| `Demos` | 可独立运行的演示 |
| `Notes/SysNotes/Guides` | 想使用模块时阅读的指南 |
| `Notes/SysNotes/Reference` | 需要查具体方法时阅读的参考 |

日常先读这张地图；真正使用某个模块时，再进入对应指南。底层模块不需要知道所有上层玩法，也不要求所有模块都经过事件总线。
